### 20. 配送遅延とレビュー評価の関係を分析

#### 実施内容
- Athenaで実際の配達日と予定配達日の差を計算
- `delivery_delay_days = actual_delivery_date - estimated_delivery_date` と定義
- 配送遅延データとレビュー評価を `order_id` で結合
- `data/analysis/delivery_delay_review_summary.csv` を作成
- Positronで基本統計量を確認
- レビュー評価別の箱ひげ図を作成
- Kruskal-Wallis検定を実施
- Dunn検定（Bonferroni補正）を実施
- 効果量 ε² を算出

#### 結果
- 分析対象：95,830注文
- レビュー評価が高いほど配送遅延日数の中央値が小さくなる傾向を確認
- 中央値：
  - Review 1：-7日
  - Review 2：-10日
  - Review 3：-11日
  - Review 4：-12日
  - Review 5：-13日
- Kruskal-Wallis検定：
  - H = 3890.1397
  - p < 0.001
- Dunn検定（Bonferroni補正）：
  - 全てのレビュー評価群間で有意差
- 効果量：
  - ε² = 0.040555

#### 解釈
レビュー評価が低い注文ほど、予定配達日との差が遅延側に位置する傾向が確認された。
統計的には各レビュー評価群間で配送遅延日数に差が認められた。

#### 注意点
- 観察データによる分析であり、配送遅延がレビュー低下を引き起こしたという因果関係は確認できない。
- 配送遅延日数には大きな外れ値が存在する。
- 箱ひげ図では表示範囲を-50〜50日に制限している。
- レビュー評価1〜5でサンプル数に偏りがある。

### 21. 低評価予測モデルの構築

#### 実施内容
- 注文金額、送料、配送遅延日数を説明変数として、低評価（レビュー1～2点）を予測するロジスティック回帰モデルを構築
- 係数をオッズ比に変換し、各変数の影響方向を確認
- 予測結果について混同行列、Accuracy、Precision、Recall、F1-scoreを算出
- ROC-AUCとROC曲線を作成
- しきい値を0.50、0.40、0.30、0.20、0.10に変更して性能を比較
- Precision-Recall曲線を作成し、PrecisionとRecallのトレードオフを確認

#### 結果
レビュー1～2点を低評価（`low_review = 1`）と定義した。

データは、

- 通常評価：87.23%
- 低評価：12.77%

であった。

説明変数として、

- `total_price`
- `total_freight`
- `delivery_delay_days`

を使用した。

ロジスティック回帰の係数は、

- total_price：0.0084
- total_freight：0.2374
- delivery_delay_days：0.7747

となった。

標準化した説明変数に対するオッズ比は、

- total_price：約1.01
- total_freight：約1.27
- delivery_delay_days：約2.17

であった。

ただし、これらは観測データに基づくモデル上の関連を示すものであり、因果関係を示すものではない。

#### モデル評価

50%をしきい値とした場合、

- Accuracy：0.8786
- Precision：0.6981
- Recall：0.0878
- F1-score：0.1560
- ROC-AUC：0.6744

となった。

しきい値を変更したところ、今回試した範囲では0.20でF1-scoreが最大となった。

| Threshold | Precision | Recall | F1 |
|---:|---:|---:|---:|
| 0.50 | 0.6981 | 0.0878 | 0.1560 |
| 0.40 | 0.7105 | 0.1544 | 0.2537 |
| 0.30 | 0.6778 | 0.2663 | 0.3824 |
| 0.20 | 0.4176 | 0.3828 | 0.3994 |
| 0.10 | 0.1701 | 0.7006 | 0.2738 |

しきい値を下げることでRecallが上昇する一方、Precisionが低下するトレードオフを確認した。

#### 今回理解したこと

- ロジスティック回帰では、低評価になる確率を予測できる
- 係数を指数変換することでオッズ比として解釈できる
- Accuracyだけではクラス不均衡のある分類問題を十分に評価できない
- Precision、Recall、F1-scoreを目的に応じて使い分ける必要がある
- ROC-AUCは分類能力をしきい値全体で評価する指標である
- PR曲線ではPrecisionとRecallのトレードオフを確認できる
- しきい値はモデルそのものとは別に調整できる
- 実務ではTestデータを使ってしきい値を決定せず、Validationデータでしきい値を決定してからTestデータで最終評価する

### 23. 月別・顧客州別の売上基準集計
#### 指標の定義
- 対象注文：`orders.order_status = 'delivered'`で、購入日・商品明細・顧客州が確認できる注文
- 集計粒度：購入月 × 顧客州
- GMV：注文に含まれる商品価格（`order_items.price`）の合計。送料は含めない
- 送料：`order_items.freight_value`の合計として別に集計
- 平均注文額：GMV ÷ 注文数
- 購入月は配送日ではなく`order_purchase_timestamp`を基準にした

#### 集計結果
- 期間：2016年9月～2018年8月（23か月。2016年11月は該当注文なし）
- 集計行数：556行（月・州の組み合わせ）
- 対象注文数：96,478件
- GMV合計：13,221,498.11（データ上の金額単位）
- 送料合計：2,198,275.64（GMVには含めず別集計）
- 全体の加重平均注文額：137.04（GMV合計 ÷ 注文数合計）
- SP州：40,501件、GMV 5,067,633.16で州別の注文数・GMVが最大。州別平均注文額は125.12
- 月別GMV最大：2017年11月の987,765.37（7,289件）
- 月・州の重複行、欠損値はなく、各行の平均注文額はGMV ÷ 注文数と一致した

#### 解釈と注意点
- SP州は取扱規模が最も大きい一方、平均注文額は全体平均を下回る。商品カテゴリや注文商品構成を追加で確認するための仮説候補とし、この差だけから施策や原因を断定しない。
- 2016年9月・10月・12月はそれぞれ1件、265件、1件と初期期間の件数が少ないため、通常月との比較や傾向判断に使う際は注意する。
- GMVは売上の代理指標であり、原価・販売手数料・広告費等がないため利益は算出できない。集計は観察データの記述であり、施策の因果効果を示さない。
- Athena結果CSVはローカルの`data/`に保存し、公開リポジトリには含めない。

```text
複数カテゴリ情報
```

を候補とする。

また、顧客ごとの過去購買行動として、

```text
prior_order_count
is_repeat_customer
prior_customer_gmv
prior_avg_order_value
days_since_previous_order
```

なども候補とする。

顧客履歴特徴量では、
対象注文より未来の購買情報を使用するとデータリークになるため、
必ず対象注文より前の履歴のみを用いて算出する。

#### モデル選択方針

現時点ではロジスティック回帰での検証を継続する。

まず、

- 時期情報
- 商品カテゴリ
- 顧客履歴

まで特徴量を追加し、
ロジスティック回帰で得られる性能を十分に検証する。

その後、
同一の特徴量セットを用いて、

- Random Forest
- Gradient Boosting系モデル

などの分類手法を比較する。

これにより、
特徴量追加による改善と、
分類アルゴリズム変更による改善を分けて評価する。

#### 次の作業

- `purchase_month_num` を季節カテゴリに置き換えたモデルを検証
- 商品カテゴリ特徴量を追加
- 顧客の過去購買履歴特徴量を追加
- ロジスティック回帰の最終的なValidation性能を確認
- その後、Random Forest・Boosting系モデルと比較
- 最終モデル決定後にHoldoutで最終評価

#### 時期特徴量の表現方法を比較

`purchase_month_num` を1〜12の数値として扱う方法に加えて、
時期情報の表現方法を見直した。

まず、月をブラジルの季節区分に変換し、
`season` をカテゴリ特徴量としてOne-Hot Encodingした。

```text
Summer : 12, 1, 2
Autumn : 3, 4, 5
Winter : 6, 7, 8
Spring : 9, 10, 11
```

Validationで評価した結果、

```text
Threshold    0.25
Precision    0.5927
Recall       0.4905
F1           0.5368
ROC-AUC      0.7656
```

となり、
`purchase_month_num` を使用したモデルよりF1が低下した。

季節への変換では12か月の情報を4区分へ圧縮するため、
月ごとの細かな違いが失われたことが一因と考えられる。

また、Validation期間が2018-01〜2018-04であり、
含まれる季節が限定される点も考慮する必要がある。

#### 月の周期性をsin / cosで表現

月ごとの情報を維持しながら、
12月と1月が隣接する周期性を表現するため、
月をsin / cosへ変換した。

```text
month_sin = sin(2π × purchase_month_num / 12)
month_cos = cos(2π × purchase_month_num / 12)
```

これにより、
月を円周上の座標として表現し、
12月と1月を近い値としてモデルへ与えられる。

`purchase_month_num` を除外し、
`month_sin` と `month_cos` を使用したモデルをValidationで評価した。

```text
Threshold    0.26
Precision    0.6117
Recall       0.5021
F1           0.5515
ROC-AUC      0.7670
```

時期特徴量の表現方法を比較すると、

```text
purchase_month_num
F1          0.5511
ROC-AUC     0.7667

season
F1          0.5368
ROC-AUC     0.7656

month_sin / month_cos
F1          0.5515
ROC-AUC     0.7670
```

となった。

`month_sin` / `month_cos` による改善幅は小さいものの、
月を単純な1〜12の数値として扱うよりも周期構造を適切に表現でき、
性能も悪化しなかった。

そのため、
今後のモデルでは時期特徴量として

```text
month_sin
month_cos
```

を使用する方針とする。

#### 次の作業

次の特徴量群として、
注文の商品カテゴリ情報を追加する。

`main_category` として注文単位に作成し、

### 44. 顧客の過去購買履歴を特徴量として追加

#### 目的

これまでのモデルでは主に、

- 注文金額
- 送料
- 配送遅延
- 注文構成
- 地域
- 購入時期
- 支払い方法
- 商品カテゴリ

そこで、
顧客の過去の購買行動にも低評価リスクに関する情報が含まれる可能性を考え、
`customer_unique_id` を用いて顧客履歴特徴量を作成した。

未来情報によるデータリークを防ぐため、
各注文より前の購買履歴のみを使用した。

#### 顧客履歴特徴量の作成

Athenaで注文を顧客ごと・購入日時順に並べ、

```text

prior_customer_gmv
prior_avg_order_value
days_since_previous_order
```

各特徴量の意味は以下の通り。

```text

prior_customer_gmv
対象注文より前の累計購入金額

prior_avg_order_value
対象注文より前の平均注文金額

前回注文から対象注文までの経過日数
```

現在の注文を過去累計値へ含めないよう、
SQLのWindow関数では現在行の1つ前までを集計対象とした。

#### データ確認

顧客履歴特徴量データは98,666注文となり、
`order_id` の重複は0件であった。

過去注文回数の分布は以下の通り。


となり、

`prior_customer_gmv` と `prior_avg_order_value` は
0が大半である一方、一部に大きな値が存在したため、
ロジスティック回帰では対数変換した特徴量を使用した。

```text

log_prior_avg_order_value
```

`days_since_previous_order` は初回購入では定義できないため欠損となる。

初回購入かどうかは `is_repeat_customer` で区別できるため、
モデル入力時には0で補完した。

#### 顧客履歴特徴量を追加したモデル

顧客履歴特徴量を追加しても、

今回のデータではリピーター注文が約3.3%と少なく、

### 45. 低評価と将来再購入率の関連分析

#### 目的

これまで、注文金額・送料・配送遅延・商品カテゴリ・顧客履歴などを用いて、低評価予測モデルを構築してきた。

しかし、低評価を予測することがビジネス上どのような価値を持つかは、十分に検証できていなかった。

そこで、低評価となった注文と通常評価の注文について、その後90日以内の再購入率・注文数・GMVを比較し、低評価と将来の顧客行動の関連を検証した。

#### 1. 観測期間の確認

Athenaで注文データの期間を確認した。

```text
全注文数          99,441
最古購入日時      2016-09-04
最新購入日時      2018-10-17
```

月別注文数を確認したところ、2018年8月までは各月数千件の注文が存在したが、9月以降は急減していた。

```text
2018-08    6,512件
2018-09       16件
2018-10        4件
```

そのため、実質的な観測終了日を2018年8月31日と仮定し、レビュー投稿後90日間を追跡できる注文を分析対象とした。

#### 2. レビュー起点データの作成

レビュー投稿後の購買行動を分析するため、購入日時ではなく `review_answer_timestamp` を起点とした。

有効なレビュー日時と評価を持つレコードを抽出し、同一注文に複数レビューが存在する場合は、最初に投稿された有効なレビューを代表値として採用した。

```text
レビュー起点データ       94,865注文
order_id重複                  0件
欠損値                        0件
低評価（1〜2点）         13,250注文
低評価率                  13.97%
```

#### 3. 90日以内の将来購買指標の作成

レビュー投稿日時を起点として、同じ `customer_unique_id` のその後90日間の購買行動を集計した。

作成した特徴量は以下の通り。

```text
future_90d_repeat
90日以内に再購入したか

future_90d_order_count
90日以内の注文回数

future_90d_gmv
90日以内のGMV（商品価格合計）
```

レビュー投稿日より前の注文および基準注文自身は将来購買として集計しないようにした。

分析対象は74,185注文となり、90日以内の再購入が確認された注文は894件であった。

#### 4. 低評価別の再購入率比較

```text

再購入数              790
再購入率          1.2499%
```

低評価群の再購入率は通常評価群より約0.30ポイント低く、相対的には約24%低かった。

#### 5. Fisherの正確確率検定

低評価群と通常評価群の90日以内再購入率を比較するため、Fisherの正確確率検定を実施した。

ただし、同一顧客による複数観測や交絡要因を考慮していないため、探索的な結果として扱う。

#### 6. 調整解析用データの整備

購入時期、顧客の過去購入回数、注文ステータスを調整するため、低評価予測モデル用データとの結合を試みた。

```text

結合失敗     2,236件
```

結合できなかった注文の低評価率は77.33%と非常に高く、完全ケース解析では選択バイアスが生じる可能性が確認された。

原因を調査したところ、商品明細が存在しない注文が、キャンセルや在庫不足などのステータスに多いことが確認された。

```text
結合失敗                   0件
```

これにより、低評価注文を含む分析対象74,185件をすべて維持できた。

#### 7. 未調整・調整ロジスティック回帰

目的変数を `future_90d_repeat`、主な説明変数を `low_review` として、ロジスティック回帰による関連分析を実施した。

```text
対象注文の購入時点より前の注文回数

```

#### 8. 顧客単位クラスターロバスト標準誤差

同一顧客が複数の基準注文として分析データに含まれる可能性があるため、`customer_unique_id` をクラスタとして標準誤差を再推定した。

#### 9. 結論

今回の分析では、低評価群は通常評価群に比べて90日以内の再購入率が低く、購入時期・過去購入回数・配送完了状況を調整した後も、その関連が認められた。

顧客単位クラスターロバスト推定では、低評価群の再購入オッズは通常評価群より約26%低かった。

ただし、これは観察データにおける関連であり、低評価が再購入率低下の原因であることを意味しない。

また、今回の分析には以下の制約がある。

- レビュー投稿日時が取得できる注文に限定される
- 観測終了日を2018年8月末と仮定している
- 未測定の交絡要因が残る可能性がある
- 過去購入回数はレビュー日時ではなく、基準注文の購入日時を起点に計算している
- 注文ステータスは配送完了の二値変数に簡略化している
- 同じ顧客が複数回登場するため、観測間に依存性がある
- 90日以内の再購入率自体が約1.2%と低く、絶対的な差は小さい

そのため、予測モデルによる顧客フォローが実際に売上や再購入率を改善するかは、別途施策検証が必要である。
